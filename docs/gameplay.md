# ゲーム仕様

[READMEに戻る](../README.md)

## コンセプトとラン

プレイヤーはプログラミング言語となり、処理要求（タスク）を実行します。コード入力は行わず、言語機能と共通の基盤強化で戦闘スタイルを組み立てます。

1. Enterまたは「ランタイムを起動」ですぐに開始。
2. WASD・HJKL・矢印キーで移動。斜め移動も同じ速度。
3. 射程内の最も近いタスクを自動攻撃する。
4. 処理後の ◆（経験値）を回収し、レベルアップで能力を選ぶ。
5. メモリが0になると終了。5分間生存するとクリア。

静的／動的型付けの事前選択・検査マーク・専用補正・節目の追加選択は撤去しました。開始時に方針を固定せず、ラン中のFeature選択で言語を作ります。

## Featureとトレードオフ

Featureは10種類から最大4種類、各4ランク。単独でも攻撃として働き、得意な状況と代償・制約で戦い方が変わります。下記は調整用の基礎値で、ゲーム内では説明文と数値欄を分けます。

| Feature | 攻撃・成長 | トレードオフ・制約 |
| --- | --- | --- |
| Garbage Collection | 基礎3秒ごとの周囲攻撃。威力48→102、半径133→187 | 回収直後に通常攻撃だけ0.18秒待機。移動・他Feature・飛んでいる弾は継続 |
| Concurrency | 通常攻撃の異なる対象+1 / ランク | 単発威力×0.92 / ランク。複数対象への総威力は増えるが、単体戦は苦手 |
| OOP | 自律オブジェクト+1 / ランク。威力26→44、基礎間隔0.9秒、射程235 | オブジェクトの維持に最大メモリ6 / ランクを予約 |
| Functional Programming | 通常弾の連鎖+1 / ランク。基礎連鎖射程155、連鎖ごとに威力85%を維持 | 合成準備に通常攻撃の基礎間隔+0.04秒 / ランク。同じ連鎖は同じ敵を再処理しない |
| ベクトル化 / Vectorization | 直線貫通弾。威力42→78、基礎幅12→24、基礎間隔2.8秒 | 発射後の追尾なし。隊列を揃える位置取りが必要 |
| Lazy Evaluation | 敵が接近すると起動する設置攻撃。起動時の威力68→128、持続攻撃13.6→25.6 / 0.6秒、基礎半径105→150、起動後2.4秒間は持続攻撃と減速 | 設置位置は固定。0.35秒の準備後、半径の65%以内に敵が入ると起動。未起動寿命7秒、最大3個 |
| Memoization | 独立した処理弾。基礎間隔1.5秒、初回威力30→66。保存済み入力は威力1.8倍・弾速1.5倍 | 結果保存に最大メモリ8 / ランクを予約。通常の計算要求・バッチは保存できるが、メモリ確保・RPC・コピー生成・ロック操作は保存しない |
| JIT Compilation | 撃破で0〜100の最適化ゲージを獲得。残量に比例して通常攻撃を高速化。満タン時+90→165% | 毎秒9減少。攻撃するだけでは維持できず、継続的な撃破が必要 |
| 非同期ストリーム / Async Stream | 別々の対象へ1→2→2→3本を接続して継続攻撃。1回の威力14→26、基礎間隔0.25秒、射程は通常攻撃と共有 | 接続ごとに0.30→0.26→0.22→0.18秒の準備。対象の撃破・射程外への移動で切断し、次の接続も準備から開始 |
| Ownership | 近距離の範囲攻撃。威力40→82、基礎半径105、基礎間隔1.6秒。近距離撃破で2→5回復 | 敵に近づいて戦う必要がある。回復予算6→12 / 秒を全攻撃で共有。召喚コピー・ロックノードでは回復しない |

### 効果と表示の共有

- 戦闘とカードの数値比較は同じ `BuildStats` を使用する。
- GCの待機はプレイヤーの移動や入力を止めない。通常攻撃をまとめて再生することもない。
- Concurrencyの減衰は通常弾とそこから生じる連鎖に反映。OOP・GCなどの独立攻撃には反映しない。
- メモ化の入力キーは「計算の種類＋入力バリエーション」。姿と足元の点で識別し、結果がある入力を優先攻撃する。
- メモ化は初めての入力や再利用できないタスクにも通常の処理弾を撃つ。再攻撃予約や再帰的な攻撃生成はしない。
- OOPとメモ化の予約は加算。両方を最大ランクにしても、Infraなしの最大メモリは44を残す。OOPの各オブジェクトは独立して対象を選ぶ。
- 関数型の合成準備は通常攻撃だけに適用し、コンパイラ最適化とJITは準備込みの間隔を短縮する。
- 所有権で実際に回復した時だけ、処理した敵からプレイヤーへ緑のメモリ粒子が戻り、プレイヤー上とHUDに「+N MB」を0.9秒間表示する。短時間の複数回復は表示中の実回復量を合算。満タン時・予算を使い切った時・対象外のコピーやノードでは回復表示を出さない。
- メモリ予約はカードで取得後の現在値／最大値を比較する。取得時の現在メモリは新しい最大値までに制限し、低メモリ時はさらに減らさない。
- 非同期ストリームはランク2・4で接続数が増える。各接続は異なる対象を選び、準備と攻撃タイマーを独立して持つ。接続中に対象を切り替えず、途中で近い敵が現れても現在の処理を継続。通常攻撃・移動は継続し、JITやConcurrencyの補正はストリームへ重ねない。コンパイラ最適化は継続攻撃の間隔と接続準備を短縮し、広域化は接続の射程を伸ばす。
- 遅延評価は接近で一度だけ起動し、残った領域は0.6秒ごとに起動時の20%のダメージを与える。起動後に入った敵も対象。領域を離れた敵には作用しない。起動済みの領域には回転する内側の弧と攻撃時の強調表示を追加。持続時間・周期はコンパイラ最適化で変えず、再設置の間隔だけを短縮する。
- 接続準備中は破線と進捗、継続中は流れる四角いデータ片と対象の枠で表示。未取得・ラン再開始時には接続を保持しない。
- JITは通常タスクの撃破で9、召喚コピーで2、ロックノードで4、ボス本体で30を加算し、100で制限。消えたノードや退場した敵からは獲得しない。通常攻撃だけでなく他Featureの撃破も対象。通常攻撃の速度倍率は `1 + 最大速度補正 × ゲージ/100`。
- JITゲージと現在の連射倍率はサイドバー、残量はプレイヤー下にも表示。一時停止・選択中は減らず、次のランへは持ち越さない。取得カードは最大倍率と毎秒の減少を示し、ステータス比較は現在のゲージ残量を共有する。
- GCは0.75秒の全範囲表示・内側へ回収するブロック・GC文字・専用SEで発動を示す。プレイヤー周囲の小さな弧は次の回収までの進捗。
- 攻撃・設置・回復予算・ボス・予告は、停止や能力選択中に進まない。ラン開始時にリセットする。

Null Safetyは安全性の仕組みを再検討するため取得候補から外しました。旧Pattern Matchingの貫通挙動はベクトル化へ継承し、図鑑の既存記録を保つため内部IDとアセット名 `patternMatching` を維持します。

## 共通Infra

Infraは7種類から最大4種類、**すべて最大6ランク**です。特定Featureの取得を前提にしません。

| Infra | 効果 / ランク |
| --- | --- |
| Memory Expansion | 最大メモリ+25、取得時に現在メモリ+35。新しい最大値で回復を制限 |
| Clock Speed | 基本移動速度+8% |
| Cache Locality | 経験値回収半径+22、基本の索敵範囲+12 |
| Compiler Optimization | 通常攻撃と全Featureの攻撃間隔×0.92。ストリームの接続準備も短縮。GCの待機・JITゲージの増減・被弾後の無敵時間は変更しない |
| Transfer Bandwidth | プレイヤー弾速×1.15。上限1600。キャッシュ弾にも上限を適用 |
| 広域化 / Spatial Expansion | 基本射程・攻撃半径・連鎖距離・オブジェクト射程・貫通弾幅に+10% |
| Memory Protection | 被弾後の無敵時間+0.08秒 |

OOP専用のCoprocessorはコンパイラ最適化へ統合しました。旧空間インデックスは、通常攻撃から使える広域化に変更。旧命令パイプラインも統合済みです。未使用IDは発見記録の互換性のため保持します。

## 敵と処理の性質

| タスク | 初登場 | 行動・判断 |
| --- | --- | --- |
| リクエスト | 開始時 | 基本の計算要求。追跡して接触攻撃。繰り返す同じ入力にメモ化を使える |
| 割り込み | 20秒 | 素早く追跡するタスク。予告や追加の突進は設けない |
| バッチ処理 | 30秒 | 同じ処理のデータ4体が32間隔の隊列で進む。先頭を処理した後も残りは追跡を継続。貫通・範囲・結果の再利用が有効 |
| メモリ確保 | 40秒 | 通常リクエストの3倍の耐久と遅い移動で接近。大きな積層ブロックと銅色で、紫色のバッチと区別。継続攻撃が有効 |
| タイムアウトRPC | 50秒 | 発光して要求弾を送信し、応答待ち後に再送。初回1発→再送2発→最大3発の扇状射撃。待機は再送段階に応じて長くなる |
| タイマーイベント | 65秒 | 時計の目盛りが満ちると、二つの隙間がある輪状パルスを発射。移動する輪を避け、開いた部分を通って接近する |
| メモリリーク | 90秒 | 近距離の間合いを保ち、解放されないメモリの領域を足元に残す。領域を避けるか発生源を先に処理する |
| Fork Bomb | 100秒 | 本体は間合いを保ち、コピーを送り込む。親は2体、1世代目は各1体まで追加生成し、2世代目は生成しない。親の処理で追加生成を停止 |
| デッドロック | 75・165・255秒 | ロックを結ぶ障壁で進路を狭め、本体も接触まで追跡する。ノードを処理して循環を解き、本体への攻撃機会を作る |

Null参照・重複リクエスト・撃破後爆発・支援・装甲は今回の出現と図鑑から外しました。既存IDを別の敵へ使い回さず、古い発見記録は保存したまま表示対象から除外します。重複入力は専用の敵種ではなく、リクエストやバッチの共通の性質です。

メモリ確保は既存の内部ID `2` と発見記録を維持して復帰。半径21、速度40、接触ダメージ15、処理時の経験値9。特定Featureへの耐性は設けず、通常攻撃でも処理できる。メモリ領域の確保は計算結果の再利用に当たらないため、メモ化の結果保存は対象外。

RPCは基礎耐久の3.6倍。距離320まで接近して通常攻撃の初期射程より外から発射し、230より近づかれると後退する。移動で追いかければ接近できる。初回から0.65秒の構えの後、弾速180で固定方向へ発射します。狙いは構えの開始時に固定。再送で扇の弾数が増え、待機は3.4→4秒。長い予告線を使わず、発光・再送段階・弾で状態を示します。処理するまで撃ち続けますが、弾数は上限以上に増えません。

Fork Bombのコピーは親ごとに最大6体、全体上限も共有。親への参照は子孫で共通とし、親を処理・退場させると子からの追加生成も停止します。コピーの経験値は1で、回復の無限生成を防ぎます。

間合いはRPCが230〜320、Fork Bombの本体が190〜260、メモリリークが110〜180、タイマーが210〜280。遠ければ接近、近ければ後退し、その間ではメモリリークだけ周回、他は停止します。後退・周回にも遅延評価の減速を適用。プレイヤーより遅いので、追えば接近できます。RPC・コピー生成・タイマーの構え中は位置を固定し、コピー自身は間合いを取らず接触まで追跡します。

### メモリリークとタイマーイベント

- メモリリークは基礎耐久の1.8倍・速度32・半径17。間合いに入ると、距離を維持したまま時計回り／反時計回りに周回し、異なる位置へ領域を散布する。周回方向は各個体の入力バリエーションで固定。プレイヤーから360以内で、2.2秒ごとに足元へ領域を配置する。処理時の経験値は7。
- 領域は22単位の四角いセル12個を組み合わせた3形状。配置も格子へ揃え、欠け・段差・枝分かれ、内部のブロックと流れる小片でメモリの漏出を表現。円や外接矩形ではなく、描いたセルとの接触で判定する。
- 配置後0.55秒で有効化し、寿命は8秒。滞在中のダメージは8で、通常の被弾後の無敵時間を共有。複数セル・複数領域の重なりでも加算しない。
- 発生源1体につき最大3領域、全体20領域。発生源を処理・退場させると領域は無害な灰色になり、1.25秒以内に消える。自然消滅前にも輪郭と内部表示を薄くする。領域は攻撃対象・経験値・回復源にしない。
- タイマーイベントは基礎耐久の3.2倍・速度38・半径16。距離210〜280を保ち、構えの間は停止する。処理時の経験値は7。
- パルスは目盛りによる1秒の準備後に放ち、4.4秒待って次の準備へ入る。二つの隙間は準備開始時にランダムに決めて固定。中心間を隙間の幅+約34度以上離して重なりを防ぎ、対角には固定しない。長い予告線は使わない。
- 輪は速度145で半径24から320まで拡大。幅8・隙間は各60度、接触ダメージ12。輪の内側と隙間は安全。判定は前フレームからの拡大範囲と端部の太さを含み、速いフレームでもすり抜けにくくする。
- パルスは全体8個まで。本体の処理で次の発射は止まり、すでに放った輪は最後まで進む。
- 両タスクともメモ化の結果保存対象外。特定Featureの取得を必須にせず、通常攻撃で処理できる。領域・パルス・発射周期は一時停止や選択中に進まず、ラン開始時にすべてリセットする。

### デッドロックの遭遇

- 本体の基礎耐久は `1800 + 出現時刻×4`。ロックノード3個の耐久は `140 + 本体の最大耐久×0.055` で、独立した耐久バーを表示。
- 再構成時点のプレイヤー方向へノードを展開する。中心は本体との間、左右は同じ前方距離から130ずつ横へ広がる。ノード間2本と本体から左右への2本、計4本の障壁が直接接近する進路を塞ぐ。
- 本体は速度40で接触まで追跡し、途中の距離で停止しない。接触ダメージは22。遅延評価の減速も適用するが、速度倍率は最低0.8。ノードの隊列は本体へ追従しながら、プレイヤー側へ毎秒最大0.6ラジアンで旋回する。前方距離も毎秒最大60の速度で調整し、中央のノードがプレイヤーと本体の間へ戻る。横移動に瞬時には追従しないので、回り込む余地を残す。本体の残り耐久が半分以下で再構成すると横幅は160ずつへ広がる。
- 新しい障壁は1.4秒間の破線予告の後に有効化。接触16ダメージで、通常被弾と無敵時間を共有する。ノード自体は接触ダメージを持たず、移動を物理的に封鎖しない。側面や後方へ回り込むこともできる。
- どのノードでも処理すれば全障壁が消え、5.5秒間本体を攻撃しやすくなる。ロック中の本体へのダメージは通常の15%。完全耐性は設けない。
- 解除後の再構成では、その時点のプレイヤー方向に向き直して再び予告から展開する。
- 本体を処理するとノードと障壁が消える。解除時に消える他のノードから、撃破報酬や回復を重複して得ない。
- HUDには本体の耐久と「ロックを処理／本体を処理」の状態を表示。「エリート」という区分は表示しない。
- 既存のデッドロックが残っている場合、次の時刻には追加出現しない。クリア条件は5分生存で、処理するか避けるかもプレイ上の選択。

### 出現と上限

45秒ごとにラッシュが発生し、次の6編成を順番に使います。初回出現時期を無視して敵を前倒しせず、上限・予算も共有します。HUDとログに編成名を表示します。

| 時刻 | 編成 | 増えるタスク |
| --- | --- | --- |
| 45秒 | 割り込み集中 | 割り込み |
| 90秒 | メモリ・RPC集中 | メモリ確保・RPC |
| 135秒 | コピー増殖 | Fork Bomb・バッチ |
| 180秒 | リーク多発 | メモリリーク・割り込み |
| 225秒 | イベント集中 | タイマー・RPC |
| 270秒 | 複合過負荷 | 複数の特殊タスク |

ラッシュ開始時に `18 + ラッシュ回数×3` 回の出現を試み、9秒間出現間隔を短縮します。終盤のラッシュは12秒間。特殊タスクの比重を編成ごとに増やしますが、同時出現上限は越えません。

通常出現間隔は `max(0.20, 0.70 / (1 + 経過秒 / 120))`。開始時0.70秒、1分で約0.47秒、2分で0.35秒、3分で0.28秒へ短くなり、ラッシュの合間も処理量が増えます。各回は1回の編成生成を試みるので、バッチなら複数体、上限到達時は生成しません。

この通常間隔に、ラッシュ中は×0.55、残り1分（240秒）からは×0.68、残り30秒（270秒）からは×0.42を適用。出現時耐久は240秒から×1.20、270秒から×1.45。さらに6秒ごとに7回／12回の追加出現を試みます。HUD・ログ・画面の縁の色で高負荷／過負荷を示します。

特殊編成の通常予算は18、残り1分で26、残り30秒で34。ラッシュ中はさらに+6。コストはバッチ4体で4、メモリ確保1体で2、RPC1体で3、タイマー1体で2、メモリリーク1体で3、Fork Bombの親1体で4。未登場の編成の初回分を予約します。

通常の種類別上限はバッチ20・メモリ確保6・RPC4・タイマー3・メモリリーク3・Fork Bombの親2。終盤の各段階でバッチは+4、他は+1ずつ増やします。メモリリークの通常出現比重も引き上げています。

通常出現・コピー生成は総数232体以内にし、デッドロックと再構成用の余地を確保します。総数上限240、敵弾96、貫通弾12、追尾弾384、設置攻撃3。親や先頭が遠方へ退場した場合も、子の行動を失効・切り替えます。

## 選択・図鑑・言語プロフィール

- 能力選択は重複なしの3択。両カテゴリに候補があればFeatureとInfraを各1つ以上含む。レベル5以降は取得済みFeatureを重み付けする。
- 取得済みのランク強化は新しい枠を使わない。満枠では未取得候補を除外し、最大ランクも除外する。
- 残り候補が1〜2ならその枚数。すべての強化後はメモリを35回復する。
- 能力選択にフォーカスがある間は、矢印4方向の押下・リピート・解放を処理し、移動キーがブラウザやページ内スクロールへ渡らないようにする。Tabによるカード移動と数字による取得は維持。
- 数字1 / 2 / 3、Tab→Enter、クリックで取得。初期フォーカスは選択エリア全体。Tabで1枚目へ入り、枠線で示す。初期Enterでは取得しない。
- 開始前のトップ画面にはメモリ・残り時間・レベル・経験値・停止ボタンを表示しない。ラン開始後にHUDを表示する。
- PC画面ではプレイヤーとデッドロックのゲージの高さ・太さを共有し、文字拡大時も整列を維持する。
- ゲーム描画領域にカードを重ね、通常HUDと現在ビルドを保持。説明・数値・使いどころはホバーなしで読める。
- 新規の能力値は値だけ、既存値の変化は矢印。変わらない値は繰り返さず、デメリットの数値を色で区別する。
- 図鑑のFeatureは「名前・特徴・トレードオフ」、Infraは「名前・効果」の2列。敵は「名前・特徴・有効な機能」。説明文で細かい数値仕様を繰り返さない。

終了時は「Javaっぽい言語」のように、取得したFeatureとランクからGo・Java・Scala・Rust・Python・Ruby・JavaScriptなどの設計への近さを表示します。型付けは判定条件にしません。主に伸ばした機能も説明し、未分類の構成は「独自設計の言語」とします。実際の言語との同一性や、静的／動的型付けを断定するものではありません。

## 保存と音声

Esc / Pで停止・再開。非アクティブ時も自動停止します。設定を閉じた後は再開操作が必要。日英の切り替えで進行は保持します。

言語・音量・ミュート・発見記録をブラウザに保存。初期音量100%。戦闘中はBGM「Runtime Loop」を再生し、停止・選択・設定・終了では停止、再開時は続きから再生します。クリア時は戦闘BGMを止め、ド→ミ→ソの上昇からド・ミ・ソ・高いドの和音で終えるファンファーレを再生します。音程の下降を使わず、最後の和音を少し保ってから減衰させ、下降する敗北音と区別します。ミュート・音量設定は両方に適用。ランの途中保存・共有は未対応です。

## 次のプレイで確認する点

- OOPの火力とメモリ予約、関数型の連鎖と発射間隔の変化が、説明と戦闘の両方から伝わるか。
- JITの撃破による上昇と時間減少が分かり、ゲージを維持する動機になるか。
- メモリ確保がバッチと見分けられ、頑丈な敵として位置取りに影響するか。
- 非同期ストリームの短い準備を視認でき、頻繁な対象変更の制約と複数接続の成長を実感できるか。
- RPC・タイマーがすぐ消えずに攻撃の役割を果たし、接近して優先処理する動機になるか。
- 所有権の回収量が、攻撃エフェクトや経験値と区別して分かるか。
- 遅延評価の起動と持続領域を見分け、敵を領域へ誘導する位置取りが生まれるか。
- メモリリークの欠けた部分が安全と分かり、タイマーの隙間を見て避けられるか。両者が同時に出ても逃げ道が残るか。
- 初回Featureのどれを選んでも単独で処理を進められるか。
- 隊列・再送・コピー生成に、それぞれ異なる対処をしたくなるか。
- デッドロックの前方のロックを狙うか回り込むかを選べ、解除後の短い攻撃機会を実感できるか。
- 6編成のラッシュの違い、残り1分・30秒の切迫感が伝わるか。
- 型付けの別ループを外した状態でも、ラン中に言語を設計していると感じられるか。

数値は仮調整です。統合テストは全時間帯の状態遷移・上限・リセットを確認するためメモリを補充しており、勝率や実プレイの難易度を保証するものではありません。
